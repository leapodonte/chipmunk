## 2. 域名与备案（第一优先，09-09 前完成提交）

1. 在阿里云注册域名（万网），实名认证，等待实名生效（约 1–3 个工作日，未生效不能备案）。
2. 备案：阿里云控制台 → 备案 → 首次备案。需要主体（公司）营业执照、法人身份证、网站负责人身份证与手机号、幕布拍照（阿里云现多为 App 人脸核验）。备案要求主体有一台阿里云中国大陆节点服务器且购买时长满 3 个月，所以 **ECS 要在提交备案前买好，且选包月 ≥3 个月**。
3. 备案审核：阿里云初审 1–2 个工作日 → 管局审核 3–20 个工作日。期间域名不可解析到大陆服务器提供服务。
4. 备案通过后 30 日内做公安联网备案（网站底部需展示备案号与公安备案号）。
5. 备案期间的替代方案：test 环境用 `http://<ECS公网IP>:9998` 直连（小程序开发者工具勾选「不校验合法域名」，`manifest.json` 的 `mp-weixin.setting.urlCheck` 保持 `false`）。**注意小程序体验版/正式版不允许 IP 与非 https，所以备案是上线硬前置。**

## 3. ECS 购买与网络

### 3.1 购买要点

- 地域：华东1（杭州），与 OSS 同地域。
- 镜像：Ubuntu 24.04 LTS 64 位。
- 系统盘：ESSD 40 GB；数据盘：ESSD 60 GB（勾选「随实例释放」否，避免误删）。
- 网络：默认 VPC；分配公网 IPv4；带宽按上表。
- 登录：创建密钥对，不用密码登录。
- 时长：包月 ≥ 3 个月（备案要求）。

### 3.2 安全组规则

入方向（其余全部拒绝）：

| 协议 | 端口 | 源 | 说明 |
| --- | --- | --- | --- |
| TCP | 22 | 办公/家庭固定 IP，或用堡垒/Workbench | SSH，**禁止 0.0.0.0/0** |
| TCP | 80 | 0.0.0.0/0 | HTTP（跳 HTTPS） |
| TCP | 443 | 0.0.0.0/0 | HTTPS |
| TCP | 9998 | 0.0.0.0/0 | 备案前的 test 直连端口，备案后删除此规则 |

出方向：允许全部。

数据库 5432、Redis 6379 **一律不开公网**，只在 Docker 内部网络互通。

## 4. 服务器初始化

以下命令以 root 登录后执行一遍即可。

```bash
# 4.1 基础更新与时区
apt-get update && apt-get -y upgrade
timedatectl set-timezone Asia/Shanghai
apt-get -y install curl wget vim git unzip htop ufw fail2ban ca-certificates gnupg lsb-release

# 4.2 创建部署用户（CI 用这个账号登录）
adduser --disabled-password --gecos "" deploy
usermod -aG sudo deploy
mkdir -p /home/deploy/.ssh && chmod 700 /home/deploy/.ssh
# 把 CI 的公钥写入（GitHub Secrets 里存对应私钥 ECS_SSH_KEY）
vim /home/deploy/.ssh/authorized_keys
chmod 600 /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh

# 4.3 SSH 加固
sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart ssh

# 4.4 防火墙（安全组之外再加一层）
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 9998/tcp     # 备案通过后执行 ufw delete allow 9998/tcp
ufw --force enable

# 4.5 swap（8G 内存给 4G swap，防止编译或峰值时 OOM）
fallocate -l 4G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
sysctl -w vm.swappiness=10 && echo 'vm.swappiness=10' >> /etc/sysctl.conf

# 4.6 挂载数据盘（假设为 /dev/vdb，先用 lsblk 确认）
lsblk
mkfs.ext4 /dev/vdb
mkdir -p /data
echo "$(blkid -s UUID -o value /dev/vdb) /data ext4 defaults 0 2" >> /etc/fstab
mount -a && df -h /data

# 4.7 安装 Docker 与 Compose 插件
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://mirrors.aliyun.com/docker-ce/linux/ubuntu $(lsb_release -cs) stable" > /etc/apt/sources.list.d/docker.list
apt-get update
apt-get -y install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
usermod -aG docker deploy
systemctl enable --now docker

# 4.8 安装 ossutil（备份上传用）
curl -o /usr/local/bin/ossutil https://gosspublic.alicdn.com/ossutil/1.7.19/ossutil64
chmod +x /usr/local/bin/ossutil
# 交互式配置：endpoint 填内网 oss-cn-hangzhou-internal.aliyuncs.com
ossutil config

# 4.9 目录规划
mkdir -p /data/ytzj/{postgres,redis,logs,uploads-tmp,backup,admin-dist,certs}
mkdir -p /opt/ytzj
chown -R deploy:deploy /data/ytzj /opt/ytzj
```

Docker 日志限制（否则日志会撑爆磁盘）：

```bash
cat > /etc/docker/daemon.json <<'EOF'
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "50m", "max-file": "5" },
  "registry-mirrors": ["https://<你的加速地址>.mirror.aliyuncs.com"]
}
EOF
systemctl restart docker
```

### 5.4 nginx 配置

`/opt/ytzj/nginx/nginx.conf`：

```nginx
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log warn;
events { worker_connections 4096; }

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;
    log_format main '$remote_addr - $time_iso8601 "$request" $status $body_bytes_sent '
                    '"$http_referer" "$http_user_agent" rt=$request_time '
                    'trace=$upstream_http_x_trace_id';
    access_log /var/log/nginx/access.log main;

    sendfile on;
    tcp_nopush on;
    keepalive_timeout 65;
    server_tokens off;
    client_max_body_size 20m;          # 上传兜底；正常走 OSS 直传不经过这里

    gzip on;
    gzip_min_length 1k;
    gzip_comp_level 5;
    gzip_types application/json application/javascript text/css text/plain application/xml image/svg+xml;

    # 限流：API 每 IP 20 r/s，突发 40
    limit_req_zone $binary_remote_addr zone=api_rl:10m rate=20r/s;
    limit_conn_zone $binary_remote_addr zone=api_conn:10m;

    include /etc/nginx/conf.d/*.conf;
}
```

        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

### 5.5 证书

方案 A（推荐，省事）：阿里云数字证书管理 → 申请免费 DV 证书 → 下载 `nginx` 格式 → 上传到 `/data/ytzj/certs/` → `docker compose exec nginx nginx -s reload`。证书 90 天或 1 年，到期前手动更换并在日历上设提醒。

### 5.6 部署与回滚脚本

`/opt/ytzj/deploy.sh`：

```bash
#!/usr/bin/env bash
set -euo pipefail
SHA="$1"
REG="<acr-registry>"
cd /opt/ytzj

echo "$SHA" > .last_deploy_candidate
sed -i "s#^API_IMAGE=.*#API_IMAGE=${REG}/ytzj/api:${SHA}#" .env.prod

docker compose -f docker-compose.prod.yml --env-file .env.prod pull api
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d api

# 健康检查，30 次 x 2 秒
for i in $(seq 1 30); do
  if curl -fsS http://127.0.0.1:9998/healthz >/dev/null 2>&1; then
    echo "$SHA" > .current_sha
    echo "deploy ok: $SHA"; exit 0
  fi
  sleep 2
done

echo "health check failed, rolling back"
PREV=$(cat .current_sha)
sed -i "s#^API_IMAGE=.*#API_IMAGE=${REG}/ytzj/api:${PREV}#" .env.prod
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d api
exit 1
```

数据库迁移策略：**迁移与发布分离**。EF 迁移脚本先在 test 执行验证，prod 由人工在发布窗口执行 `docker compose exec api dotnet Ytzj.Api.dll --migrate`，确认无误后再滚动新镜像。禁止应用启动时自动迁移（一旦失败会反复重启）。

## 6. OSS 设计与配置

### 6.1 桶创建

控制台 → OSS → 创建 Bucket，四个桶参数如下（地域一律华东1 杭州）：

| Bucket | 读写权限 | 版本控制 | 服务端加密 | 用途 |
| --- | --- | --- | --- | --- |
| `ytzj-public-prod` | 公共读 | 开启 | OSS 完全托管 | 内容图片/视频、头像、Banner、分享卡片 |
| `ytzj-private-prod` | 私有 | 开启 | OSS 完全托管 | 自测照片、模拟前后图、复诊监控照、口扫模型、医生认证材料 |
| `ytzj-public-test` | 公共读 | 关闭 | 默认 | 测试 |
| `ytzj-private-test` | 私有 | 关闭 | 默认 | 测试 |

版本控制开启的理由：误删或误覆盖医疗影像不可恢复，代价远高于存储费。

### 6.5 直传策略签发（服务端）

`POST /app/file/upload-policy` 返回的字段与 OSS PostObject 表单一一对应：

```csharp
// 伪代码：生成 policy
var expire = DateTimeOffset.UtcNow.AddMinutes(10);
var key    = $"assess/{userId}/{recordId}/{slot}.jpg";       // 服务端决定
var policyDoc = new {
    expiration = expire.ToString("yyyy-MM-ddTHH:mm:ss.fffZ"),
    conditions = new object[] {
        new object[] { "content-length-range", 0, 10 * 1024 * 1024 },   // ≤10MB
        new object[] { "eq", "$key", key },                              // 精确到 key，杜绝越权写
        new object[] { "in", "$content-type", new[]{ "image/jpeg", "image/png" } }
    }
};
var policy    = Base64(Json(policyDoc));
var signature = Base64(HmacSha1(policy, ossAccessKeySecret));

// 回调：上传成功后 OSS 主动通知我方登记 file_object
var callback = Base64(Json(new {
    callbackUrl      = "https://api.<主域名>/open/oss/callback",
    callbackBody     = "bucket=${bucket}&key=${object}&size=${size}&mimeType=${mimeType}"
                       + "&height=${imageInfo.height}&width=${imageInfo.width}"
                       + "&bizType=${x:biz_type}&userId=${x:user_id}&fileId=${x:file_id}",
    callbackBodyType = "application/x-www-form-urlencoded"
}));
```

响应给客户端：
```json
{ "code":0, "data":{ "uploads":[{
  "file_id":"01J...", "key":"assess/01J.../front.jpg",
  "host":"https://ytzj-private-prod.oss-cn-hangzhou.aliyuncs.com",
  "ossaccessid":"LTAI...", "policy":"eyJ...", "signature":"xxx",
  "callback":"eyJ...", "expire":1789000600,
  "x_vars":{ "x:biz_type":"assess_photo", "x:user_id":"01J...", "x:file_id":"01J..." }
}]}}
```

小程序端上传：
```ts
uni.uploadFile({
  url: data.host,
  filePath,
  name: 'file',
  formData: {
    key: data.key,
    OSSAccessKeyId: data.ossaccessid,
    policy: data.policy,
    Signature: data.signature,
    callback: data.callback,
    ...data.x_vars,
    success_action_status: '200',
  },
})
```

**OSS 回调验签**（服务端必做，否则任何人都能伪造上传完成）：
1. 取请求头 `x-oss-pub-key-url`，Base64 解码得到公钥地址。
2. **校验该地址 host 必须是 `gosspublic.alicdn.com`**，否则直接拒绝（这是该机制的经典漏洞点）。
3. 下载公钥（带本地缓存），用 RSA-SHA1 验证 `Authorization` 头对 `path + "\n" + body` 的签名。
4. 验签通过后按 `file_id` 幂等写入 `ops.file_object`，返回 `{"Status":"ok"}`。

### 6.6 私有文件读取

- 统一走 `POST /app/file/sign-url`，服务端先做归属校验（§5.4 权限模型），再生成 OSS 签名 URL，有效期默认 600 秒。
- 签名 URL 不写日志、不入库、不进分享链路。
- 医生查看患者照片同样走此接口，每次记 `ops.audit_log`。

### 6.7 生命周期规则

| 桶 | 前缀 | 规则 |
| --- | --- | --- |
| private | `export/` | 7 天后删除 |
| private | `sim/` | 180 天后转低频访问 |
| private | `assess/`、`monitor/`、`scan/` | 不删除；1 年后转低频 |
| public | `share/` | 90 天后删除（分享卡片可重新生成） |
| 两桶 | 碎片 | 清理 7 天前的未完成分片上传 |

### 6.8 服务端访问端点

ECS 上的 API 访问 OSS **必须用内网端点** `oss-cn-hangzhou-internal.aliyuncs.com`：走内网不计流量费、延迟更低。签发给客户端的直传 `host` 和签名 URL 用公网端点 `oss-cn-hangzhou.aliyuncs.com`。两者在代码里分开配置（见 `.env` 的 `OSS_ENDPOINT_INTERNAL` / `OSS_ENDPOINT_PUBLIC`）。

## 7. CDN 配置

只加速 public 桶。私有医疗影像不接 CDN（签名 URL 直连 OSS 即可，量小；接 CDN 会引入鉴权复杂度与缓存泄露风险）。

### 7.1 添加域名

阿里云 CDN → 域名管理 → 添加域名：

| 项 | 值 |
| --- | --- |
| 加速域名 | `cdn.<主域名>` |
| 业务类型 | 图片小文件（若视频占比大，另建 `video.<主域名>` 选「视频点播」） |
| 源站类型 | OSS 域名 → 选择 `ytzj-public-prod.oss-cn-hangzhou.aliyuncs.com` |
| 加速区域 | 仅中国内地 |
| 回源 Host | 源站域名（默认即可） |

添加后按提示到 DNS 把 `cdn` 记录 CNAME 到分配的 `*.w.kunlunsl.com` 之类地址。

### 7.2 关键配置项

| 配置 | 值 | 理由 |
| --- | --- | --- |
| HTTPS | 上传证书，开启，强制跳转 HTTPS | 小程序只允许 https |
| HTTP/2 | 开启 | |
| 缓存过期时间 | `jpg,png,webp,gif,mp4,woff2` → 30 天；`json` → 不缓存 | 内容媒体不变更 |
| 忽略参数 | 保留 `x-oss-process` 等图片处理参数 | 否则缩略图样式失效 |
| Range 回源 | 开启 | 视频拖动播放必需 |
| 过滤参数 | 开启但保留白名单 | 避免缓存命中率被随机参数打散 |
| Referer 防盗链 | 白名单：`servicewechat.com`、`<主域名>`，允许空 Referer | 小程序内 Referer 可能为空，必须允许 |
| 智能压缩 | 开启 | |
| 私有 Bucket 回源 | 关闭（源桶是公共读） | |
| 访问日志 | 开启，投递到 OSS | 排障与流量分析 |

### 7.3 图片样式（在 OSS 侧配置，CDN 透传）

在 public 桶 → 数据处理 → 图片样式，建三个样式，分隔符用 `!`：

| 样式名 | 参数 | 用途 |
| --- | --- | --- |
| `thumb` | `image/resize,w_400/quality,q_80/format,webp` | 列表缩略图 |
| `card` | `image/resize,w_750/quality,q_85/format,webp` | 详情主图 |
| `avatar` | `image/resize,w_160,h_160,m_fill/quality,q_85/format,webp` | 头像 |

前端拼接：`https://cdn.<主域名>/post/xxx/yyy.jpg!thumb`。`ICdnUrlBuilder` 统一封装，页面不手写。

### 7.4 视频

M2 引入。先按「直接存 mp4（H.264 + AAC，≤1080p）+ CDN 分发」，不上转码服务；上传前在客户端限制时长（建议 ≤3 分钟）与码率。若后期用户上传格式杂乱，再接媒体处理做转码。

## 8. 备份与恢复

`/opt/ytzj/backup.sh`（每日 03:00 由 cron 执行）：

```bash
#!/usr/bin/env bash
set -euo pipefail
DATE=$(date +%F)
DIR=/data/ytzj/backup
mkdir -p "$DIR"

# 1. 数据库全量
docker compose -f /opt/ytzj/docker-compose.prod.yml --env-file /opt/ytzj/.env.prod \
  exec -T postgres pg_dump -U ytzj -d ytzj -Fc \
  | gzip > "$DIR/ytzj-$DATE.dump.gz"

# 2. 上传 OSS（内网端点，不计流量）
ossutil cp "$DIR/ytzj-$DATE.dump.gz" oss://ytzj-private-prod/backup/db/ -f

# 3. 本地只留 7 天，OSS 侧生命周期留 90 天
find "$DIR" -name '*.dump.gz' -mtime +7 -delete

# 4. 配置备份
tar czf "$DIR/conf-$DATE.tar.gz" /opt/ytzj/nginx /opt/ytzj/docker-compose.prod.yml
ossutil cp "$DIR/conf-$DATE.tar.gz" oss://ytzj-private-prod/backup/conf/ -f
find "$DIR" -name 'conf-*.tar.gz' -mtime +7 -delete
```

```bash
crontab -e
0 3 * * * /opt/ytzj/backup.sh >> /data/ytzj/logs/backup.log 2>&1
```

恢复演练（**M0 内必须做一次，并记录耗时**）：

```bash
gunzip -c ytzj-2026-09-20.dump.gz > /tmp/r.dump
docker compose exec -T postgres createdb -U ytzj ytzj_restore_test
docker compose exec -T postgres pg_restore -U ytzj -d ytzj_restore_test /tmp/r.dump
# 校验行数后删除
```

另外开启 ECS 自动快照策略（每日一次，保留 7 天），作为整机级兜底。

## 11. 应急预案

| 故障 | 现象 | 处置 |
| --- | --- | --- |
| API 全挂 | `/healthz` 失败 | `docker compose logs --tail 200 api` 定位；必要时 `deploy.sh <上一个 sha>` 回滚 |
| 数据库连接耗尽 | 大量超时 | `SELECT * FROM pg_stat_activity` 找长事务；杀掉；检查是否有慢查询未加索引 |
| 磁盘满 | 写入失败 | 清 `/var/lib/docker` 悬空镜像 `docker system prune -a`；清旧日志；扩容数据盘 |
| 被刷接口 | 带宽/CPU 飙升 | nginx 层封 IP `deny`；调低 `limit_req`；必要时开启阿里云 WAF |
| OSS 回调被伪造 | 出现无主文件 | 检查验签逻辑；临时关闭回调改为客户端确认 + 服务端 HeadObject 校验 |
| 插件不可用 | 模拟一直失败 | `ai.plugin_registry` 置 `enabled=false`，前端入口自动隐藏，通知 LEO |
| 证书过期 | 全站 HTTPS 报错 | 上传新证书 `docker compose exec nginx nginx -s reload` |
| 误删数据 | 数据缺失 | 从当日 dump 恢复到 `ytzj_restore` 库，按表补回；OSS 有版本控制可恢复对象 |
