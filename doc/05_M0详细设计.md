## 2. 决策记录（ADR）

每条格式：决策 / 理由 / 备选 / 状态。状态为「已定」的写入仓库 `docs/decisions/`，后续变更需走评审。

### ADR-001 客户端形态：微信小程序，uni-app 单工程
- 决策：继续用现有 uni-app（Vue 3 + TypeScript）工程，主编译目标 `mp-weixin`，保留 `app-plus` 编译能力供第三步出 iOS App。
- 理由：09-02/08-31 已定小程序优先；现有工程已有 13 个页面、姿态检测、i18n、签名请求层，重写没有收益；一套代码将来出 App 不用第二个团队。
- 备选：原生小程序（性能略优但丢弃现有代码与 App 能力）、Taro（无迁移收益）。
- 状态：已定。

### ADR-002 后端语言与框架
- 决策：**ASP.NET Core（.NET 10 LTS）**，Web API + Minimal Hosting，部署为 Linux 自包含发布或容器。
- 理由：v1 服务从代码注释判断是 .NET（`src/utils/sign.ts` 提到「服务端 EncryptorService.RequestKey」，`vite.config.ts` 提到「API 的 HttpHeaders 中间件」），zsj 有存量经验；.NET 10 是 LTS，支持到 2028-11，覆盖三步走全程；单进程内存占用小，4C8G 单机可承载 10 万月活。
- 备选：Go（Gin/Kratos，运维更轻但需重学）、Java Spring Boot（生态全但内存开销大，单机吃紧）、Node NestJS（与前端同语言但 CPU 密集任务弱）。
- 状态：**已由本仓库现状确认**。`api/Admin.sln` 就是 ASP.NET Core net10.0，语言与框架的推断成立。但 ORM 实际用 **FreeSql** 而非本文 §3 写的 EF Core 加 Dapper，建表走 CodeFirst `SyncStructure`。本文 §5 目录结构与 §11 工时按 EF Core 估算，需按 FreeSql 修正。见 `09_设计文档与实现现状对照.md`。

### ADR-003 数据库：PostgreSQL 17，单实例多 schema
- 决策：单台 PostgreSQL 17，一个数据库 `ytzj`，**一个业务域一个 schema**；硬性规则：禁止跨 schema JOIN 和跨 schema 外键，跨域只能走服务接口或领域事件。
- 理由：09-03 定的「商城、复诊打卡、内容分库」意图是隔离与可替换。两人团队真开 8 个物理库，等于 8 套迁移脚本、8 个连接池、开发期无法快速排查数据；schema 隔离能拿到同样的边界约束，将来任何一个域要独立扩容/备份/拆服务，`pg_dump -n schema` 直接搬走即可，改动量是机械的。
- 备选：物理分库（现在过重）、单 schema（丧失边界，将来拆不动）。
- 状态：**与本仓库现状不符，本条不成立**。仓库用单个 PostgreSQL 数据库 `admin`，由 FreeSql CodeFirst 建表，没有做 schema 划分。多 schema 方案与 FreeSql 的 `SyncStructure` 流程需要额外适配。是否引入 schema 边界要重新评估，见 `09_设计文档与实现现状对照.md` 第 4 节。
- 拆库触发条件（若将来引入 schema 边界则适用）：单域表数据超 5000 万行；单域 QPS 超实例 40%；域需要独立备份周期或独立合规审计；团队增加到 4 人以上分域负责。

### ADR-004 缓存与队列
- 决策：Redis 7.4（会话、验证码、限流、计数、Streams 轻量队列）；定时与后台任务用 **Hangfire**（PostgreSQL 存储），带自带看板。
- 理由：两人团队不引入 Kafka/RabbitMQ；Hangfire 的重试、定时（换套提醒、评分结算、物流拉取）、看板开箱即用，任务状态落在同一 PG 里便于排查。
- 备选：Quartz.NET（无看板）、RabbitMQ（运维成本）、云 MNS（绑定厂商）。
- 状态：Redis 部分**已由本仓库确认**。定时任务实际用 **FreeScheduler** 而非 Hangfire，`CLAUDE.md` 与开发计划均已写明。Hangfire 的看板能力 FreeScheduler 不具备，排查手段需另想。

### ADR-005 部署形态：单台阿里云 ECS + Docker Compose
- 决策：阿里云杭州地域一台 ECS（Ubuntu 24.04 LTS，4vCPU/8GiB/100GB ESSD），Docker Compose 跑 nginx + api + postgres + redis；OSS 双桶 + CDN 承载静态与媒体。
- 理由：用户指定阿里云 Ubuntu + OSS + CDN；单机足够支撑到灰度与 2027 上半年；同地域 ECS 访问 OSS 走内网不计流量费。
- 备选：K8s/ACK（当前规模纯增负担）、RDS + Redis 云实例（更稳但月成本翻倍，可在 2027 Q1 再迁）。
- 状态：已定。迁移触发条件：日活超 2 万，或数据库 CPU 持续超 60%，则先把 PG 迁 RDS。

### ADR-006 对象存储分桶
- 决策：两个桶。`ytzj-public-{env}`（公共读、CDN 加速：内容图片/视频、头像、Banner、静态资源）；`ytzj-private-{env}`（私有、签名 URL：自测照片、模拟前后图、复诊监控照、口扫模型、医生认证材料）。
- 理由：医疗影像与身份材料属敏感个人信息，必须私有 + 短时签名；内容媒体要走 CDN 且可被搜索/分享。
- 状态：**本期不落地**。开发计划 5.4 已定为本地磁盘加预签名接口，接口语义按预签名设计，将来切 OSS 时只换读写实现。私有加短时签名这条原则两者一致，双桶与 CDN 留到切 OSS 时再用。

### ADR-007 会话与签名
- 决策：保留现有 `App-Timestamp` + `App-Signature`（HMAC-SHA256）作为**防篡改与防重放**手段，但安全边界改为「不透明会话令牌 + 服务端限流 + 敏感操作二次校验」。令牌为 32 字节随机串，存 Redis，滑动过期 30 天，头名沿用 `App-Session` 以兼容现有前端。
- 理由：签名密钥内置在小程序包里（`src/utils/sign.ts`），包可被反编译，签名不能当作身份凭证；但保留它能挡住绝大多数脚本刷接口，且不改前端。
- 状态：机制**已由本仓库确认**（`EncryptorService.SignRequestBody`，Redis 会话）。两处参数不同：仓库的会话是 60 分钟滑动过期而非 30 天，签名时间戳容差是 ±15 分钟而非 ±5 分钟，且多一个 `App-RequestId` 头。以仓库为准。

### ADR-008 ID 生成：ULID
- 决策：全局主键用 ULID（26 位大写字符串，时间有序），应用层生成，列类型 `CHAR(26)`。
- 理由：现有接口 ID 已是字符串；ULID 单调递增对 B-tree 索引友好，不暴露业务量（对比自增），不需要中心发号器（对比 Snowflake）。
- 状态：已定。

### ADR-009 底部 tabBar
- 决策：M1 用微信**标准 5 项 tabBar**（首页 / 发现 / 打卡 / 消息 / 我的），「打卡」是普通 tab 页；M2 若设计上需要中间凸起按钮，再切自定义 tabBar。
- 理由：杨老师要求中间加号一键打卡（09-02）。自定义 tabBar 在 uni-app 下需要额外维护原生组件目录，会拖慢 M1；标准 tab 的中间项同样是「一次点击到达」，功能等价。
- 状态：⚠ 待确认（超月向杨老师说明，09-16）。
- 补充：购物车不占 tab 位，商城入口放首页宫格 + 「我的-订单」。

### ADR-010 内容承载
- 决策：单一信息流（发现页），帖子统一模型；医生案例是带模板扩展字段的帖子；视频自托管（OSS + CDN），不外链第三方。
- 理由：09-03 决策。
- 状态：已定。

### ADR-011 商城
- 决策：接有赞类 SaaS，小程序以 web-view 整页承载或跳转其小程序；我方只存订单引用。
- 理由：09-07 决策；库存/物流/客服不自建。
- 状态：已定，具体服务商 ⚠ 待确认（超月，M2 前）。

### ADR-012 插件集成
- 决策：三类插件契约（A 类异步任务 API、B 类跳转 + webhook、C 类基础设施封装），统一注册表 + 统一签名 + 统一计量。详见 §7。
- 理由：09-07「平台是整合者」决策。
- 状态：已定，P1（AI 正面模拟）接口细节 ⚠ 待 LEO 交付（09-16）。

### ADR-013 医生端载体
- 决策：M1–M2 医生功能在同一小程序内按角色解锁；网页端在第二步做。
- 理由：09-06 决策。
- 状态：已定。

### ADR-014 运营后台技术栈
- 决策：Vue 3 + TypeScript + Vite + Element Plus，独立 SPA，走 `/admin` 接口。
- 理由：与小程序同语言，zsj 一个人维护；Element Plus 表格/表单开箱即用，后台不需要设计稿。
- 状态：**组件库与本仓库不符**。仓库定的是 **Ant Design Vue**（`backend/` 与 `doctor/` 同栈），且是两个后台而非一个。以仓库为准。

### ADR-015 前端 TypeScript 升级
- 决策：`typescript` 从 4.9 升到 5.x，`vue-tsc` 同步升级。
- 理由：4.9 已过旧，`satisfies`、`const` 类型参数等对接口类型定义有实际帮助；uni-app 当前版本兼容。
- 状态：已定（M0 内完成，作为仓库骨架的一部分验证）。

### ADR-016 环境划分
- 决策：三套环境 dev（本地）/ test（ECS 上独立容器与库 schema 前缀）/ prod（同机独立容器与库）。M1–M2 期间 test 与 prod 同机不同容器；prod 上线前评估是否分机。
- 理由：成本与运维量；两人团队不值得三台机器。
- 状态：已定。

模块依赖规则（写进 CI 检查或代码评审清单）：
1. `Domain.*` 之间不允许互相引用。需要对方数据时，走 `Ytzj.Api` 层编排，或发领域事件。
2. `Domain.*` 只能引用 `Shared`；`Infrastructure` 可引用所有 `Domain`（放各自 DbContext）。
3. 每个 `Domain.X` 对应且只对应 schema `x`，DbContext 里 `HasDefaultSchema("x")`。
4. 跨域读取一律通过接口（如 `IIdentityQuery.GetUserBrief(ids)`），返回 DTO，不返回实体。

## 5. 后端设计

### 5.1 请求管线（中间件顺序）

```
TraceId          → 生成/透传 X-Trace-Id，写入日志上下文与响应头
ExceptionHandler → 统一捕获，转 {code,msg,trace_id}，5xx 记 error 日志
RequestLogging   → 记录 path/耗时/用户/状态码，敏感字段脱敏
RateLimit        → Redis 令牌桶：IP 维度 + 用户维度 + 端点维度
Signature        → 校验 App-Timestamp（±300s）与 App-Signature；/open 走各自签名；multipart 跳过
Session          → 解析 App-Session → Redis 取会话 → 填充 CurrentUser（含 roles）；无会话则匿名
Authorization    → 端点声明的角色/权限；行级校验在服务层
Endpoints
```

### 5.2 统一返回

```json
{ "code": 0, "msg": "ok", "data": { }, "trace_id": "01J..." }
```
- `code=0` 成功；非 0 前端统一 toast `msg`。
- HTTP 状态码一律 200（沿用现有前端 `utils/request.ts` 的处理方式），业务状态在 `code`。
- 例外：`/open` 回调用标准 HTTP 状态码（插件方通常按状态码重试）。

### 5.4 权限模型

角色：`patient`（默认）、`doctor`（认证通过后授予）、`expert`、`ops`、`admin`。一个用户可多角色。

行级规则（在服务层强制，不依赖前端）：

| 资源 | patient | doctor | ops/admin |
| --- | --- | --- | --- |
| 自测记录/报告/照片 | 仅本人（或本设备游客记录） | 仅其疗程内患者的 | 全部（审计留痕） |
| 疗程 | 仅本人为 patient 的 | 仅本人为 doctor 的 | 全部 |
| 帖子 | 已发布的全部 + 本人全部状态 | 同左 | 全部 |
| 私信会话（M2） | 仅本人参与 | 仅本人参与 | 不可读正文，只可按投诉工单调阅并留痕 |
| 文件签名 URL | 仅本人拥有或其疗程可见 | 仅其疗程内 | 留痕 |

实现要点：所有查询强制带归属条件；禁止「先查后判」的写法（先按 id 查再比对 owner 会产生越权探测）；统一封装 `IAccessGuard.EnsureCourseAccess(courseId)`。

### 5.5 幂等

- 所有写接口支持可选头 `App-Idempotency-Key`（客户端生成 ULID），服务端在 Redis `idem:{userId}:{key}` 存 10 分钟，命中则返回首次结果。
- 强制幂等的场景：创建 AI 任务、绑定医生、发布内容、创建订单（M3）、插件回调（按 `task_id` 幂等）。

### 5.6 分页

- 列表统一游标分页：请求 `{cursor, page_size}`，响应 `{items, next_cursor, has_more}`。
- `cursor` 为服务端签名的不透明串（内容为排序键，如 `published_at + id`），避免深翻页和被构造。
- 兼容：现有 `/app/selftest/records` 是 `page/page_size`，迁移期保留，M1 结束前统一到游标。

### 5.7 日志与追踪

- Serilog 结构化输出到 `/var/log/ytzj/api-*.log`（JSON 行），按天轮转保留 30 天。
- 每条日志带 `trace_id`、`user_id`、`endpoint`、`elapsed_ms`。
- 敏感字段（手机号、验证码、令牌、身份证、OSS 私有 key）在序列化时脱敏。
- 慢请求（>1s）与所有 5xx 单独打 warn/error，便于 grep。

## 7. 插件契约 V1

### 7.1 插件注册表

所有外部能力在 `ai.plugin_registry` 注册，运行时可开关、可灰度、可切换实现。关键列：

| 列 | 说明 |
| --- | --- |
| `plugin_id` | 全局唯一，如 `leo-sim-frontal-v1` |
| `type` | `A`/`B`/`C` |
| `capability` | 能力标识，如 `sim.frontal_align`、`design.retainer`、`shop.mall` |
| `endpoint` | 基础 URL |
| `auth_type` / `auth_ref` | `hmac` / 密钥在配置中心的引用名（不入库） |
| `timeout_ms` / `retry` | 默认 60000 / 2 |
| `billing` | `{"unit":"call","price":0.35,"currency":"CNY"}` |
| `enabled` / `gray_rate` | 开关与灰度比例（0–100） |

路由规则：按 `capability` 找出 `enabled=true` 的插件，按 `gray_rate` 与用户 ID 哈希选择。同能力可并存多个实现，替换供应商不改业务代码。

### 7.2 A 类：异步任务 API（AI 模拟、图像质检、后续 AI 对比）

```

Headers: X-Timestamp, X-Nonce, X-Signature（同算法，密钥同一把）
Body:
{
  "task_id": "01J8ABCDEF...",
  "provider_task_id": "p_123",

  "outputs": [

```

**约定**
- 插件不得持久化输入图片超过 24 小时；不得用于训练以外的用途；训练用途需另行书面约定。
- 超时（默认 60s）后我方标记 `failed`，前端提示「稍后再试」，不阻塞其他功能。
- 失败重试 2 次，退避 5s/20s；连续失败率 10 分钟内超 30% 自动置 `enabled=false` 并告警。

## 10. CI/CD 与协作规范

### 10.1 分支

- `main`：可部署，受保护，只接受 PR。
- `feature/<域>-<简述>`：功能分支，一个功能一个分支。
- `fix/<简述>`、`chore/<简述>`。
- PR 必须由另一人评审（zsj ↔ LEO 交叉），CI 绿才可合并。

### 10.2 GitHub Actions

`backend.yml`：PR 时 restore/build/test；push 到 `main` 时构建镜像推到阿里云容器镜像服务（ACR），SSH 到 ECS 执行 `deploy/scripts/deploy.sh`。

```yaml
name: backend
on:
  pull_request: { paths: ["backend/**"] }
  push: { branches: [main], paths: ["backend/**"] }
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with: { dotnet-version: "10.0.x" }
      - run: dotnet restore backend/Ytzj.sln
      - run: dotnet build backend/Ytzj.sln -c Release --no-restore
      - run: dotnet test backend/Ytzj.sln -c Release --no-build
  deploy:
    needs: build
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Login ACR
        run: echo "${{ secrets.ACR_PASSWORD }}" | docker login ${{ secrets.ACR_REGISTRY }} -u ${{ secrets.ACR_USERNAME }} --password-stdin
      - name: Build & push
        run: |
          IMAGE=${{ secrets.ACR_REGISTRY }}/ytzj/api:${{ github.sha }}
          docker build -t $IMAGE -f backend/Dockerfile backend
          docker push $IMAGE
      - name: Deploy over SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.ECS_HOST }}
          username: deploy
          key: ${{ secrets.ECS_SSH_KEY }}
          script: /opt/ytzj/deploy.sh ${{ github.sha }}
```

`miniprogram.yml`：`npm ci` → `npm run build:mp-weixin` → `miniprogram-ci upload` 到体验版（需要小程序上传密钥，存 GitHub Secrets，且 CI 出口 IP 要加入微信 IP 白名单；若不便，改为本地脚本上传）。

`admin.yml`：build 后 rsync 静态文件到 ECS 的 `/opt/ytzj/admin-dist`，由 nginx 托管。
