## 3. 客户端架构

### 3.1 小程序（uni-app）

- 技术栈保持现状：Vue 3 + TypeScript + Pinia + vue-i18n，`vite-plugin-uni`。
- 角色渲染：登录后拉取 `roles`（patient / doctor / expert），页面与 tab 项按角色显示；医生功能不单独成包，放在分包内按需加载。
- 分包规划（主包 ≤ 2 MB，总包受微信上限约束）：
  - 主包：首页、发现流、打卡、消息、我的、登录与协议。
  - 分包 selftest：自测问卷、拍照引导、相机（含姿态检测）、报告。
  - 分包 simulate：AI 模拟上传、结果对比、分享。
  - 分包 care：复诊监控、换套任务、历史对比。
  - 分包 trade：订单、物流、套餐、商城入口。
  - 分包 doctor：患者列表、看板、发布案例、二维码、方案入口。
  - 分包 webview：通用 web-view 承载页（供应商设计、商城 H5）。
- 状态管理：Pinia 按域拆 store（user、course、checkin、feed、message、order），持久化只保留会话与轻量缓存。
- 网络层：沿用 `utils/request.ts` 的封装，增加统一错误码处理、重试与埋点；上传统一走对象存储直传（服务端签发临时凭证），大文件不经过 API。
- 条件编译：App 端保留（`APP-PLUS`）以便第三步输出 iOS App；姿态检测已按平台分流。
- 视频：使用小程序 `video` 组件播放 CDN 地址，播放域名加入合法域名；上传走直传。

### 3.2 医生网页端 / 运营后台

- 单页应用（建议 Vue 3 + TypeScript，与小程序共享类型定义与部分工具），走 `/doctor` 与 `/admin` 接口。
- 医生网页端第二步上线；运营后台第一步最小可用（审核、用户/医生管理、认证、消息模板、订单查看、数据）。
- 供应商设计软件的桌面版评审可直接超链接跳转，携带一次性签名 token 单点登录。

### 3.3 web-view 承载的插件页

- 小程序 web-view 只能整页承载，因此供应商设计、有赞商城以「整页 H5」方式接入，返回时通过 URL 参数或服务端回调带回结果。
- 业务域名需在微信后台配置并完成校验文件；H5 页面需 HTTPS。
- 我方在 web-view 外层提供统一的标题、返回与加载失败兜底。

### 5.2 统一插件契约

```
插件注册表 plugin_registry
  plugin_id, type(A/B/C), version, endpoint, auth(方式与凭证引用),
  capabilities[], sla(超时、重试), billing(计量单位、单价), enabled, gray_rate

A 类任务协议（复用现有 analysis 任务模式）
  创建：POST /internal/ai/tasks {plugin_id, input_refs[], params} → task_id
  状态：status(queued/running/succeeded/failed), progress, stage, result_refs[]
  回调：POST /open/plugins/{plugin_id}/callback（签名校验、幂等）
  计量：每次成功写 plugin_usage，供对账与限额

B 类跳转协议
  发起：服务端生成一次性 token（含 user、course、order、回跳地址，短期有效）
  承载：小程序 web-view 打开供应商/商城 H5
  回传：URL 参数带 result_id，或 webhook 写入订单/方案状态
  幂等：以外部单号为键

C 类基础设施
  统一封装为服务端 SDK 层，业务代码不直接依赖具体云厂商接口
```

契约要点

- 数据主权：照片、口扫、方案结果最终都回存我方，插件只拿短期有效的签名 URL。
- 故障隔离：插件超时或失败不阻塞主流程；功能入口受 `enabled` 与灰度开关控制。
- 可替换：同一 `capability` 可注册多个插件，按路由规则切换；替换供应商时业务代码不改。
- 计费：所有外部调用计量入账，月度对账；设计费 50–100 元/次一类的按次成本可归到订单。

## 6. 关键流程

### 6.1 扫码绑定医生

1. 医生端请求带 `scene=doctor:{id}` 的小程序码，可保存相册与转发。
2. 患者扫码进入 → `wx.login` → 服务端 code2session → 创建/找回用户 → 记录 `qr_scene`。
3. 首次用户完成偏好问卷 → 创建疗程（状态：咨询中）→ 绑定为该医生患者 → 医生收到通知。
4. 已有疗程的用户扫另一医生码：提示当前疗程，选择结束并新建或仅关注。

### 6.2 AI 模拟引流

1. 上传照片（相册或拍摄）→ 端侧轻量质检 → 直传对象存储。
2. 创建 A 类任务 → 插件处理约 30 秒 → 回调写结果 → 小程序轮询/推送刷新。
3. 结果页：前后对比 + 免责 + 相似案例（按标签/偏好）+ 推荐医生（同城优先）+ 分享。
4. 游客可用，保存需登录；每日次数限制由配置控制。

### 6.3 打卡与评分

1. 点击加号 → 服务端按上一事件类型判定本次为戴/摘 → 写 `checkin_event`。
2. 周期结束（或每日定时）计算总时长、连续性、均衡性 → 加权得分写 `wear_score`。
3. 医生看板汇总疗程内患者得分；低分触发提醒（阈值可配）。

### 6.4 复诊监控与换套提醒

1. 医生或患者设置副数与周期 → 生成 `aligner_schedule`。
2. 定时任务在换套前一天与当天发系统通知 + 微信订阅消息（订阅授权在打卡或设置时收集）。
3. 患者完成换套任务：拍照上传（旧套/新套）→ 写 `monitor_photo` → 第二步接入 AI 对比插件。
4. 医生查看并反馈（评论或私信）。

### 6.5 保持器订单全链路

1. 患者或医生发起需求 → 订单创建（待口扫）。
2. 口扫在诊所完成，STL/PLY 上传建档（医生端或运营代传）。
3. 服务端生成 B 类跳转 token → 医生在 web-view/桌面打开供应商设计 → 供应商 webhook 回传方案编号与状态。
4. 专家/医生确认 → 生产 → 发货单号回传 → 物流状态同步 → 患者与医生均可查看。
5. 到期复购提醒；订单与疗程关联。

### 6.6 私信

1. 患者对绑定医生或医生对患者发起 1:1 会话。
2. 消息落库 → 未读计数 → 对方在线则长连接/轮询刷新，离线则订阅消息或模板消息触达（受微信频率限制，需在关键节点收集授权）。
3. 医生端支持集中回复列表。

## 8. 微信平台要点

| 项 | 要点 |
| --- | --- |
| 登录 | `wx.login` → code2session 得 openid/unionid；手机号用短信验证码或 `getPhoneNumber`（需企业主体） |
| 订阅消息 | 换套提醒、打卡提醒、订单状态、私信触达；一次性订阅需在用户操作节点收集授权，模板需申请 |

| web-view | 业务域名白名单、校验文件、HTTPS；整页承载 |
| 支付 | 微信支付商户号；医疗器械类目资质；套餐周期扣款走支付宝签约 |
| 内容安全 | UGC 文本与图片调用内容安全接口，审核状态写 moderation |

## 9. 安全与合规

- 现状：请求签名密钥内置于小程序代码（`utils/sign.ts`），小程序包可被反编译，签名只能防误用不能防伪造。建议：签名保留，安全边界改为会话令牌 + 服务端限流 + 关键操作二次校验（短信/微信）。
- 会话：`App-Session` 改为带过期与刷新的令牌；医生与运营端使用独立令牌与更短有效期。
- 权限：按角色与疗程归属做数据行级校验（医生只能读自己疗程内的患者）。
- 敏感数据：手机号加密存储；照片与口扫仅签名 URL 访问，默认 10 分钟有效；导出与删除留审计。
- 合规文案：AI 结果免责、非诊断口径、未成年人提示、肖像授权勾选、数据授权书；由配置中心统一下发，便于法务更新。
- 内容治理：UGC 先审后发或机审后发可配置；举报与封禁流程。
- 日志与审计：运营操作、医生查看患者数据、数据导出记录审计。
