## 1. 产品定位

### 1.1 一句话定位

面向正畸人群的「医生 + 患者 + 门诊 + 供应商」四端协作服务平台。以微信小程序为唯一用户入口，以小红书式内容和 AI 牙齿模拟引流，以打卡与复诊监控留存，以保持器、微调牙套和隐形矫治器（自有 OEM 产品）变现。

### 1.2 商业主线（决定优先级的依据）

| 层级 | 内容 | 在产品中的角色 |
| --- | --- | --- |
| 核心收入 | 隐形矫治器（目标 200 元/副，每位患者 5000–10000 元）、保持器（终身需求）、微调牙套 | 所有模块最终托举「医生与患者在平台上闭环一个 case」 |
| 留存收入 | 终身服务套餐（保持无忧、牙周护理、家庭套餐；年付） | 让患者在矫正结束后仍留在平台 |
| 周边收入 | 商城（牙膏、冲牙器、美白剂、保持器等）、广告位、导流佣金 | 不是主业，用现成 SaaS 承接 |
| 引流工具 | AI 正面排齐模拟（后续侧貌、贴面、美白）、自测问卷、内容信息流 | 低成本获客，转化到医生绑定 |

### 1.3 三阶段（详见 `02_产品实现Roadmap_三步走.md`）

1. 保持器切入 + 平台骨架（2026 Q4 局部上线）。
2. 保持器 + 轻微微调（2027）。
3. 完整正畸平台与规模化推广（2028 起）。

### 1.4 明确不做

- 不做预约系统（与诊所现有系统冲突、运营过重）。
- 不做远程会诊/会议系统，医患视频沟通用微信。
- 不做第二套医生 App；医生高级功能用网页端。
- 不自建商城库存、物流、客服。
- 不以「AI 诊断」「在线治疗」作为对外承诺；不使用杨老师个人 IP。
- 初期不在商城上架正畸类产品。

## 2. 用户与角色

| 角色 | 定义 | 进入方式 | 核心诉求 |
| --- | --- | --- | --- |
| 游客 | 未登录用户 | 搜索、分享链接、投放 | 玩 AI 模拟、看内容 |
| 患者（普通用户） | 已注册用户，可绑定医生 | 医生二维码、患者邀请、自然流量 | 变美、省钱、被监督、有人回答问题 |
| 医生 | 认证后的超级用户，主体是全科牙医 | 运营邀请入驻 + 认证 | 拉新与管理患者、看数据、发布内容、拿到方案支持、降低复诊频次 |
| 专家 | 中心化方案团队成员 | 运营分配 | 在方案设计流程中出/审方案 |
| 门诊/机构 | 医生所属机构 | 医生关联或运营录入 | 品牌露出、获客 |
| 供应商 | 牙套/保持器设计生产方、周边品牌 | 系统对接 | 订单流、曝光 |
| 运营 | 平台内部人员 | 网页后台 | 内容审核、用户/医生管理、商城运营、数据看板 |

角色权限矩阵、医生认证材料与审核流程：PM 需产出。

## 3. 核心业务规则（已定部分）

### 3.1 注册与登录

- 微信小程序静默登录获取 openid；手机号通过验证码绑定（已定为首选，微信一键授权手机号待公司主体认证后评估）。
- 注册时填写偏好问卷（十几题），用于推荐「患者最喜欢的方案」与内容。
- 未成年人（儿童早矫场景）需监护人提示。

PM 需产出：偏好问卷题目与选项、每题映射的推荐维度；登录页与协议勾选文案；游客可用范围。

### 3.2 医患关系与疗程

- 患者通过医生二维码/邀请码进入即绑定为该医生患者；直接搜索进入的用户可浏览与使用引流工具，可主动选择医生发起咨询。
- 医患多对多；唯一性单位是「疗程」（一个患者与一个医生的一段治疗）。换医生 = 结束当前疗程、开启新疗程，历史数据保留。
- 医生看到的是自己疗程内的患者数据。

PM 需产出：疗程状态机（咨询中 / 进行中 / 已结束 / 保持期）、切换医生的规则与提示、无医生状态下的功能可用范围、医生拒绝/接受患者的机制。

### 3.3 裂变与积分

- 层级：医生 → 患者 → 患者，最多两层；患者邀请的人必须挂靠该患者的医生。
- 积分来源：邀请注册、发布牙套日记/内容、完成打卡等不产生消费的行为。
- 积分用途：周边产品、优惠券（向门诊争取）、保持器。
- 「患者合伙人」按消费分成模式：待法务评审，暂不进产品。
- 医生积分：推广患者数、患者平台消费额、内容数量与质量 → 排名与广告位。

PM 需产出：积分规则表、奖励目录、防刷规则、医生排名算法权重与展示位置。

### 3.4 打卡评分

- 摘/戴双打卡，底部中央加号一键操作，系统按上次状态自动判断本次是「戴上」还是「摘下」。
- 周期：默认 14 天一副，医嘱可改。
- 评分权重：总时长 60%、连续性 30%、均衡性 10%；医患都能看图表。
- 低于阈值（会上提到 70 或 80 分）触发干预：待定。
- 不做防作弊。

PM 需产出：三项指标的计算定义、图表类型、阈值与干预动作、漏打卡补录规则、多副牙套切换时的处理。

### 3.5 复诊监控

- 换套提醒：提前一天 + 当天；消息中心与微信订阅消息。
- 换套时引导拍照上传（旧套状态与新套状态），医患可见；平台侧 AI 对比 + 医生查看，初期后台可人工。
- 拍照频率：隔几天到一周提醒一次。

PM 需产出：拍照规范（角度、数量）、AI 对比结果的呈现（脱套、不贴合等标签）、医生处理动作、宣传口径与免责文案。

### 3.6 内容

- 单一小红书式信息流，帖子统一模型（图文/视频），作者类型：医生、患者、官方；内容类型：科普、案例、牙套日记、互助求助。
- 医生案例按模板提交（前后照片必填、视频可选、文字说明）；医生有个人主页，可被关注。
- 过滤：只看医生 / 只看患者 / 按类型；推荐：按注册问卷偏好与浏览停留做多维匹配。
- 视频自托管，不外链第三方。
- 前期由运营小号活跃社区。

PM 需产出：帖子字段、案例模板、审核流程（发布前审 / 发布后审）、举报机制、肖像授权勾选、推荐维度表。

### 3.7 消息与沟通

- 站内 1:1 私信（医患），配微信推送；医生可集中回复。
- 医生主页留言、帖子评论。
- 不引导加微信；不做视频会诊。

PM 需产出：私信发起权限（患者主动 / 仅绑定医生）、未读与推送策略、敏感词与合规提示。

### 3.8 商城

- 有赞类 SaaS 承接商品、库存、支付、物流、客服；小程序内展示与下单。
- 平台自营选品，医生不能上架；初期不上正畸类产品；美白剂可关联打卡。

PM 需产出：首批选品清单、页面承载方式（小程序内嵌 vs 跳转）、订单在「我的」中的呈现。

### 3.9 保持器与牙套订单

- 流程：需求登记 → 诊所/口扫点口扫 → 设计（供应商软件或自研模块）→ 专家/医生确认 → 生产 → 发货 → 物流跟踪 → 复购提醒。
- 医患都能看到订单与物流进展。
- 设计费 50–100 元/次由供应商侧计费；供应商有二类证可直接出货。
- 微调套餐：Mini 3–5 副、Standard 6–10 副、Pro 10–15 副（第二阶段）。

PM 需产出：订单状态机、每一步的责任角色与通知、口扫数据的授权与保存、退换货规则、价格展示。

### 3.10 服务套餐

- 类型建议：保持无忧（保持器损坏免费换、反弹免费做几副微调）、牙周护理、家庭套餐。
- 年付，支付宝周期扣款；对外称「服务」，不称保险。

PM 需产出：套餐内容与定价、签约门诊的履约流程、续费与退费规则、法务口径。

### 3.11 医生端

- 与患者同一小程序，认证后解锁：我的患者列表与数据看板、我的二维码、发布案例/科普、私信患者、方案设计入口（跳转供应商）、专家支持。
- 网页端：团队协作、报表、批量操作、牙套设计评审（后期）。
- 运营后台：内容审核、用户/医生管理、商城运营、数据看板。

PM 需产出：医生首页信息层级、患者列表筛选维度、数据看板指标、认证流程。

### 3.12 合规与文案

| 可以用 | 避免用 |
| --- | --- |
| 牙齿健康自测、AI 辅助模拟、正畸后保持管理、保持器复购、口扫建档、佩戴提醒、反弹监控、轻微微调适合度评估、合作机构服务 | AI 诊断、AI 确诊、在线治疗、医生确诊、AI 自动治疗方案、保证不反弹/排齐/变美、无需面诊、无需医生、完全替代隐形正畸、杨老师推荐/团队 |

- AI 模拟结果统一附一行免责：AI 生成，仅供参考，最终以医生评审为准，不作为签约依据。
- 用户侧文件：用户协议、隐私政策、照片/口扫数据授权书、自测免责声明、医疗服务边界说明、未成年人监护人提示。
- 宣传可强调「AI 辅助」，但不承诺诊疗效果。

## 5. 功能模块详述

每个模块给出：目标 / 主要用户 / 核心流程 / 已定 / 待定 / PM 产出 / 阶段。

### 5.1 AI 牙齿模拟（引流小游戏）

- 目标：让用户上传一张照片就看到「排齐后的自己」，产生分享与转化。
- 用户：游客、患者，也供医生给患者做演示。
- 流程：上传/拍摄正面照 → 轻度质检（有脸、有牙、清晰）→ 提交 AI 任务 → 约 30 秒返回前后对比 → 推相似真实案例 → 推医生（同城优先）→ 推价格/咨询入口 → 分享。
- 已定：正面排齐用 LEO 现成模型，任意角度、可夸张；取消评分；结果附免责；侧貌、贴面（DSD）、美白模拟作为后续玩法并入同一入口。
- 待定：游客是否可用（建议可用，保存结果需注册）；每日次数限制；分享卡片样式；侧貌模拟操作者定位。
- PM 产出：上传引导文案与失败提示、结果页布局（滑杆对比 / 左右对比）、推荐案例与医生的排序规则、分享文案。
- 阶段：一。

### 5.2 牙齿自测问卷与报告（现有功能改造）

- 现状：四类自测、≤10 题、引导拍照、评分与微笑类型报告、自动保存（已开发）。
- 已定：评分体系弱化，报告以风险提示、标签与建议为主；问卷需重新设计准确性；标签用于推荐。
- 待定：是否保留「微笑类型」作为趣味元素；与注册偏好问卷的关系（建议合并为一次进入流程）。
- PM 产出：新问卷题库、报告结构、与模拟入口的衔接。
- 阶段：一（改造）。

### 5.3 牙套打卡

- 见 3.4。页面：打卡主页（大按钮 + 当前状态 + 今日时长）、周期日历、评分图表（时长/连续/均衡）、历史记录、医嘱设置（副数、周期）。
- 阶段：一。

### 5.4 复诊监控

- 见 3.5。页面：换套倒计时、换套任务（拍照上传）、历史对比时间轴、医生反馈。
- 阶段：一（提醒 + 拍照上传 + 医生查看）；AI 对比在二。

### 5.5 内容中心（发现）

- 见 3.6。页面：信息流、详情、发布（图文/视频模板）、医生主页、患者主页、关注列表。
- 待定：帖子是否需要审核后发布；视频时长与大小上限；话题/标签体系。
- 阶段：一（框架 + 官方内容 + 医生案例）；社区互助与推荐算法在二。

### 5.6 专业方案与方案设计（医生侧）

- 目标：医生为患者发起保持器/微调/矫治方案，由供应商软件设计、中心专家审核。
- 已定：供应商软件通过跳转或整页 web-view 接入，前端风格尽量一致；专家端在方案设计流程内；医生可见方案，患者看医生转述。
- 待定：接入哪家（美立克 / 昆山供应商）、计费口径、回传哪些数据（方案编号、副数、预计周期）。
- PM 产出：方案发起表单、状态流转、医生与专家的分工界面。
- 阶段：一（跳转 + 状态回传）；二（深度整合）。

### 5.7 保持器与牙套订单

- 见 3.9。页面：需求登记、口扫预约信息（线下完成）、订单详情与物流、复购提醒。
- 阶段：一（保持器）；二（微调套餐）；三（隐形矫治全流程）。

### 5.8 找医生 / 找机构 / 找产品

- 找医生：列表 + 筛选（性别、年龄段、学历、区域、擅长：美学/舌侧/隐形/儿童早矫）+ 医生主页（简介、案例、机构与地点、二维码）。
- 找机构：大众点评式（资质、环境、服务、评价、地理位置）。
- 找产品：四类预设（隐形矫正、舌侧、唇侧固定、儿童早矫）+ 品牌广告 + 支持该技术的医生/机构。
- 待定：机构数据来源与录入方式、评价体系是否开放。
- 阶段：一（找医生基础版）；二（找机构、找产品）。

### 5.9 商城

- 见 3.8。阶段：一（接入展示 + 下单）。

### 5.10 服务套餐

- 见 3.10。阶段：二。

### 5.11 消息中心

- 见 3.7。阶段：一。

### 5.12 我的 / 账户

- 资料、疗程、报告与模拟记录、订单、积分与邀请、设置与协议。
- 阶段：一。

### 5.13 医生端（小程序角色 + 网页端）

### 5.14 运营后台

## 6. 关键用户旅程（PM 需逐条写成用户故事与页面流）

1. 患者扫医生二维码首次进入 → 静默登录 → 偏好问卷 → 绑定医生并创建疗程 → 进入首页看到疗程卡片。
2. 用户从抖音/小红书链接进入 → 玩 AI 模拟 → 看相似案例 → 看推荐医生 → 发起咨询或私信 → 医生接受后创建疗程。
3. 已绑定患者每日打卡 → 周期结束换套提醒 → 拍照上传 → 医生查看并反馈 → 评分变化。
4. 医生在小程序发布案例（模板）→ 审核 → 出现在发现流与医生主页 → 被关注、被私信。
5. 医生为患者发起保持器订单 → 跳转供应商设计 → 专家确认 → 生产发货 → 患者在「我的订单」看物流 → 到期复购提醒。
6. 患者邀请朋友（挂靠同一医生）→ 朋友注册 → 双方积分到账 → 兑换周边/优惠券。
7. 患者购买美白剂 → 关联夜间打卡 → 商城复购。
8. 患者结束矫正进入保持期 → 购买保持无忧套餐 → 年付续费 → 保持器损坏免费更换。
9. 直接搜索进入的无医生用户 → 浏览内容 → 选择医生 → 成为其患者。
10. 患者换医生 → 结束疗程 → 新医生扫码 → 新疗程，历史数据保留。

## 7. 指标
